# Rebalances & Auctions

Rebalance APIs split live RPC state from historical API/subgraph state.

## Live State

Use live methods for automation and UI state that must reflect the chain now.

| Method                | Use                                        |
| --------------------- | ------------------------------------------ |
| `getCurrentRebalance` | Current rebalance state from RPC.          |
| `getActiveAuction`    | Active auction, if one exists.             |
| `getLatestAuction`    | Latest auction state.                      |
| `getBidQuote`         | Quote a bid against current auction state. |

```ts
const activeAuction = await sdk.index.getActiveAuction({
  address,
  chainId,
});
```

`getRebalanceNonce` reads Folio 6.0's `getRebalanceNonce()` (the value the next `startRebalance` must exceed by one);
it reverts on a v5 proxy. Both auction readers resolve one block first and pin every read to it. An auction is active only while
`startTime <= now <= endTime` (inclusive, exactly as Folio's `bid` checks) **and** its `rebalanceNonce` equals the
current rebalance nonce read at the same block; a time-valid auction left over from a previous rebalance is reported
with `isActive: false`. The result carries `currentRebalanceNonce` and `blockNumber` so callers can reason about
staleness.

## Historical State

Use historical methods for analytics and completed lifecycle views.

| Method                   | Use                               |
| ------------------------ | --------------------------------- |
| `getRebalances`          | Rebalance history.                |
| `getRebalance`           | One rebalance by ID or nonce.     |
| `getRebalanceAuctions`   | Auctions attached to a rebalance. |
| `getCompletedRebalances` | Completed rebalance history.      |
| `getCompletedRebalance`  | One completed rebalance.          |

## Auction Builders

| Method                           | Use                                                |
| -------------------------------- | -------------------------------------------------- |
| `prepareOpenAuctionArgs`         | Build v5-compatible open-auction args.             |
| `prepareOpenAuction`             | Encode a version-aware open-auction call.          |
| `prepareOpenAuctionUnrestricted` | Open an auction after the community window starts. |
| `prepareBid`                     | Bid on an auction.                                 |
| `prepareCloseAuction`            | Close an auction.                                  |
| `prepareEndRebalance`            | End the active rebalance (6.0.0: by nonce).        |

```ts
const quote = await sdk.index.getBidQuote({
  address,
  chainId,
  auctionId: 1n,
  sellToken,
  buyToken,
  maxSellAmount: 1000000000000000000n,
});

const call = sdk.index.prepareBid({
  address,
  chainId,
  version,
  auctionId: 1n,
  sellToken,
  buyToken,
  sellAmount: quote.sellAmount,
  maxBuyAmount: quote.bidAmount,
});
```

Every auction builder (`prepareOpenAuctionArgs`, `prepareOpenAuction`, `prepareOpenAuctionUnrestricted`,
`prepareBid`, `prepareCloseAuction`, `prepareEndRebalance`) and the revenue builder `prepareDistributeFees` require
`version` (`"5.0.0"` or `"6.0.0"`, read it from `getVersion`) and reject anything else with `SdkError(INVALID_INPUT)`;
there is no silent v5 default and Folio 4.x is not supported by these builders. Where the call shape is identical in
both versions the bytes are too; the ABI attached to the prepared call follows the version. For Folio 6.0 pass the positive `auctionLength` once, to the args builder: it drives
the library's v6 math and is carried into the encoded sixth argument. Use `maxAuctionLength()` from RPC unless the
rebalance's price control allows a shorter custom length.

```ts
const version = await sdk.index.getVersion({ address, chainId }); // "6.0.0"
const { args } = sdk.index.prepareOpenAuctionArgs({ ...input, version, auctionLength: 1800n });
const call = sdk.index.prepareOpenAuction({ address, chainId, version, args });
```

Folio 6.0.0 binds `endRebalance` to the rebalance it ends: pass `rebalanceNonce` (read it with `getRebalanceNonce`)
and the Folio reverts `Folio__InvalidRebalanceNonce` if a newer rebalance has started since. Folio 5.0.0 keeps the
nonce-less `endRebalance()`. On-chain, `startRebalance` and `endRebalance` also accept `type(uint256).max` to skip the
nonce check; the SDK basket builder always sends the exact next nonce.

```ts
const rebalanceNonce = await sdk.index.getRebalanceNonce({ address, chainId });
const end = sdk.index.prepareEndRebalance({ address, chainId, version: "6.0.0", rebalanceNonce });
```

Open-auction inputs are validated before the rebalance library runs: a zero, negative or non-finite current price
(or snapshot price when the target basket uses snapshot prices) throws instead of skewing weights.

## Bidding Mode

`bidsEnabled` is a DTF deployment/settings flag, not a per-rebalance flag.

- `true`: permissionless bidding.
- `false`: trusted-filler flow.

Read it with `sdk.index.getBidsEnabled({ address, chainId })`.

## Version Notes

Auction and rebalance contract signatures changed across Index DTF versions. Use SDK builders instead of hand-encoding ABI calls unless you are intentionally bypassing SDK behavior.
